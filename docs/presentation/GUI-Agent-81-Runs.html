GUI Agent in 81 Runs

An Android agent built on qwen3-vl (4B, local via Ollama): six versions, three AndroidWorld tasks, two machines. This page re-reads the raw data of every scored run: the log rows, the AndroidWorld checker result and each of the 1,094 agent steps.

What we built

Every later chart compares versions. Without knowing what differs between them, none of those comparisons can be read.

Part B

What came out

“PASS” means the agent itself reported “complete” and the AndroidWorld checker returns 1.0. For everything else we newly separate how the run failed. This needs no manual review; it follows from two fields: the checker score and whether “complete” was reported.

Part C

What it costs

Cost is the most robust result of the project. It rests on more than a thousand model calls instead of nine runs per version.

Part D

How the agent behaves

The trajectories show more than the success rates: what does the agent tap, and does the screen change afterwards?

Part E

How robust this is

Same code, same seeds, temperature 0, two machines. The model digests differ because the Ollama builds differ, so strictly speaking it is a different model.

Part F

Deliberately not shown

These charts would be the obvious choice. We leave them out because with our data they would claim more than the data supports.

Success rates as bars without intervals

56% against 22% looks like a clear difference, but with n = 9 it is within noise. Replaced by Figure 3.

Failure-class distribution as the main finding

45 of the 61 labels are unreviewed runner suggestions, and “grounding” is a catch-all (Figure 5). As a headline chart it would fake a precision we do not have. Replaced by the objective split in Figure 4.

A line from V1 to V6

A line claims a progression. But the versions do not build on each other: V4 and V5 both start from V2. That is why we use dots or bars everywhere.

Cost and success on two y-axes

Where the two curves cross depends only on how the axes are scaled, which invents a correlation that is not in the data. Replaced by the scatter plot in Figure 10.

Mac and Windows merged into one rate

Different model digests are different models (Day 1). Both machines stay separate in every chart.

Pie or donut chart of PASS/FAIL

20 against 61 is a single number. It is shown as a tile at the top; a pie would add nothing.

Radar chart of the versions

Axes with different units (seconds, tokens, percent) on one area. How large the area gets depends only on the order of the axes.

ERROR runs in rates

The 11 emulator crashes (all Mac V3) say nothing about the agent. They were re-run with the same seed and are excluded from every chart.

Mac V6 times as a cost comparison

These runs ran under other load (up to 68 s per step). They appear only marked (Figures 8 and 10) and are not read as an effect of the fixes.
